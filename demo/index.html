CORE WORKFLOWS

CrewForge combines a fast team-discovery experience with server-side membership invariants. The preview above lets you explore the product journey; the full-stack API and transaction behavior are independently inspectable in the repository and automated CI.

What to try: create a team, describe the skills you need, filter the board, run skill matching, join an open seat and leave a team. The underlying API implements moderated requests, leader decisions, idempotent retries and transactional membership changes.
Product capabilities

One workflow from discovery to team lifecycle

Discover + match

Search teams by project and skill, compare open seats, and rank recommendations by complementary skills and capacity.

Create + invite

Create a team with minimum and maximum size, then issue expiring, high-entropy invite links stored as hashes.

Request to join

Requests are idempotent and remain pending. A pending request never reserves a seat or inflates memberCount.

Leader approval

Only the current leader can accept or decline. The server rechecks authority and available capacity inside the transaction.

Maintain membership

Leaders can remove members; duplicate membership is prevented per hackathon; leadership transfers when the leader leaves.

Audit + update

Membership changes and audit events commit together. MongoDB change streams feed bounded Server-Sent Events for live board refresh.
